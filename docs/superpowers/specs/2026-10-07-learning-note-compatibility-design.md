# Learning Ops 질문별 답변 노트 호환성 설계

## 승인 범위와 원인

사용자가 승인한 범위는 기존 질문별 답변 구조 지원, 여러 답변의 종합 판정, 기존 기록과 복습 일정 유지다. 실제 노트 재현에서 자동 판정이 첫 답변과 검토 섹션을 놓쳤다. `extractSection()`은 `##` 제목만 찾지만 개인 노트 템플릿은 `## 질문별 답변` 아래 `### 질문`, `#### 답변 항목` 구조다.

## 선택한 방식

Learning Ops 내부에서 개인 노트의 답변 단위를 읽는다. 기존 `##` 단일 답변 형식도 유지한다. 공용 `extractSection()`을 넓히면 공개 질문 섹션과 저장된 질문 hash의 의미가 바뀔 수 있어 그대로 둔다. 노트를 일괄 재작성하는 방식은 사용자 기록을 바꾸므로 사용하지 않는다.

## 판정 기준

- `## 질문별 답변` 아래 각 `###` 질문을 독립 답변 단위로 읽고, `####` 첫 답변·부족한 개념·코드/문서 근거·면접용 30-60초 답변·꼬리 질문 대비·다음에 다시 볼 것을 읽는다.
- 코드 블록 안의 제목은 답변 구조로 보지 않는다. 형식 밖의 복습 로그와 메모는 답변 단위에 포함하지 않는다.
- 빈 목록, 빈 체크박스, TODO, 작성 예정, 템플릿의 안내 문장은 실제 답변으로 보지 않는다.
- 첫 답변은 어느 질문에든 실제 내용이 있으면 존재한다. 검토 완료는 모든 답변 단위에 검토 항목 2개 이상이 있을 때 계산한다.
- 질문별 면접 준비 완료는 공개 질문 세트가 있고, 공개 질문 개수 이상을 다뤘으며, 모든 답변 단위에 첫 답변과 최종 면접 답변이 있을 때 후보로 계산한다. 불확실한 첫 답변만 있고 검토가 없으면 복습 대상으로 둔다.
- 일부 질문의 답변이 빠지거나 다음에 다시 볼 항목이 있으면 복습이 필요하다. 단일 `##` 답변 형식은 기존 요약 답변 용도를 유지한다.
- 기존 manifest의 명시적 상태·기한·원문/질문 hash 우선순위는 유지한다. 파일을 읽기만 하며 노트, manifest와 발행본은 수정하지 않는다.
- 반환값은 상태와 boolean만 포함하며 실제 답변 본문은 inventory에 노출하지 않는다.

## 검증과 변경 경계

합성 노트로 실패를 확인한 뒤 수정한다. 질문 경계, 부분 답변, 템플릿 placeholder, 코드 블록, 검토 내용의 다른 질문 간 혼합, manifest 우선순위와 비공개 본문 비노출을 검사한다. 실제 로컬 노트는 읽기 전후 hash로 불변을 확인한다.

변경 대상은 `scripts/blog-ops/learning-inventory.mjs`, 관련 테스트와 운영 문서다. 공개 글 parser, progress resolver, 개인 노트와 manifest의 저장 형식은 바꾸지 않는다.
