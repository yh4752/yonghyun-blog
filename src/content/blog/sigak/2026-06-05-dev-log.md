# 2026-06-05 개발 로그: 41개 기사 검색 평가 카탈로그 준비

## 요약

오늘은 기존 6개 article smoke catalog를 덮어쓰지 않고, 현재 PostgreSQL의 API-ready article을 별도 frozen catalog로 export했다.
검색 품질을 바로 주장하는 것이 아니라, 더 큰 라벨링과 benchmark를 시작할 수 있는 평가 기준점을 만드는 데 집중했다.
실제 export 결과는 기대했던 26개보다 많은 `41`개였고, JSON schema와 중복 ID 검증을 통과했다.
새 label JSON은 아직 없으므로 retrieval/graph benchmark 재실행은 다음 단계로 남겼다.

## 오늘 완료한 일

- `experiments/datasets/raw/articles.catalog.api-ready-2026-06-05.json` 확장 catalog를 생성했다.
- 기존 `experiments/datasets/raw/articles.catalog.json` 6개 article smoke baseline을 보존했다.
- `experiments/README.md`에 smoke catalog와 확장 catalog의 차이, `expanded/` 결과 경로 원칙, 실제 article count를 기록했다.
- `docs/STATUS.md`와 `docs/STATUS.ko.md`에 확장 catalog 진행 상태와 검증 결과를 반영했다.
- 기존 6개 article catalog와 label JSON의 내용, `latest/` 결과 디렉터리 미변경 여부를 추가로 확인했다.
- 독립 리뷰 후 설계 문서의 stale expected count와 실행 계획 체크박스 상태를 실제 진행 상황에 맞게 보정했다.
- `docs/blog/topic-queue.md`에 catalog 확장과 label compatibility gate를 기술 블로그 후보로 추가했다.

## 설계 고민 / 결정

기존 `articles.catalog.json`을 덮어쓰지 않은 이유는 label과 result artifact가 특정 `catalogId`와 article ID 집합을 전제로 하기 때문이다.
6개 article smoke 결과는 runner가 end-to-end로 동작했다는 재현성 baseline이고, 41개 article catalog는 다음 평가를 위한 새 기준점이다.
따라서 새 catalog, 새 label, 새 result는 `api-ready-2026-06-05` 계열 이름으로 분리한다.

## 트레이드오프

- 얻은 것: 현재 DB 상태를 기준으로 41개 API-ready article catalog를 확보해 10-15개 query label 작성이 가능한 기반을 만들었다.
- 미룬 것: 새 label JSON 작성, retrieval benchmark 재실행, graph-aware evaluation 재실행은 사용자의 수동 라벨링 이후로 미뤘다.
- 주의점: article 수가 늘었다고 검색 품질이 좋아졌다고 말할 수는 없다. 품질 주장은 label 수, query 다양성, benchmark 결과를 함께 본 뒤에만 가능하다.

## 다음 단계

- `docs/search-evaluation/labeling.html`에서 `experiments/datasets/raw/articles.catalog.api-ready-2026-06-05.json`을 import한다.
- 10-15개 query를 만들고 각 query에 대해 strong/acceptable/not relevant label을 작성한다.
- 기존 `api-ready-2026-06-02` label을 참고하더라도 새 catalog 기준으로 다시 검토하고, 화면의 `검토 완료` 상태가 JSON의 `reviewed`로 저장되는지 확인한다.
- label JSON을 `experiments/datasets/labels/search-labels.api-ready-2026-06-05.2026-06-05.json`로 저장한다.
- catalog-label consistency validation을 통과한 뒤 retrieval/graph benchmark를 `expanded/` 경로로 실행한다.
