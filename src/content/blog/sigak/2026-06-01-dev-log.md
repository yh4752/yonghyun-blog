# 2026-06-01 개발 로그: 검색 평가 라벨링을 정적 HTML로 준비

## 요약

오늘은 hybrid search 품질을 숫자로 비교하기 전에 필요한 relevance label 입력 도구를 만들었다.
Markdown 표는 기준 설명에는 좋지만, query별로 20-30개 article을 계속 라벨링하기에는 불편하다고 판단했다.
그래서 서버나 DB 없이 브라우저에서 여는 `docs/search-evaluation/labeling.html`을 추가하고, seed catalog 기반 라벨 JSON export/import 흐름을 만들었다.
Benchmark runner와 더 큰 catalog export는 아직 구현하지 않았다.

## 오늘 완료한 일

- `docs/search-evaluation/labeling.html`
  - seed article 1-5와 starter query를 내장한 정적 HTML 라벨링 도구를 추가했다.
  - query card별로 `strong`, `acceptable`, `not_relevant`, `unlabeled`를 선택할 수 있게 했다.
  - label JSON export/import, catalog JSON import, validation warning, JSON preview, `localStorage` draft 저장을 추가했다.
  - storage가 막혀도 화면이 깨지지 않도록 draft 저장/삭제/복구를 방어적으로 처리했다.
  - catalog import 시 중복 article ID를 거절해 label identity가 섞이지 않게 했다.
- `docs/search-evaluation/queries.md`
  - Markdown은 가이드이고 실제 입력은 `labeling.html`을 우선 사용한다는 안내를 추가했다.
- `docs/STATUS.md`, `docs/STATUS.ko.md`
  - retrieval benchmark 라벨링 도구가 준비됐고, 아직 seed catalog 기반이라는 점을 반영했다.
- `docs/ROADMAP.md`, `docs/ROADMAP.ko.md`
  - Research dataset/label 단계에 정적 라벨링 UI 준비를 표시했다.
  - 다음 benchmark 작업을 frozen catalog export, human labeling, benchmark runner로 분리했다.

## 설계 고민 / 결정

처음에는 `queries.md` 표를 직접 채우는 방식으로도 시작할 수 있었다.
하지만 article 수가 늘어나면 표가 너무 커지고, 대부분의 article이 특정 query와 관련 없기 때문에 사용자가 매번 `not_relevant`를 직접 채우는 구조는 부담이 크다.
그래서 기본값을 `unlabeled`로 두고, `reviewed` query에서는 라벨이 없는 article을 benchmark 계산 시 관련 없음으로 해석하는 방향을 유지했다.

React 화면이나 DB-backed admin UI도 선택지였지만 이번 단계에서는 제외했다.
아직 필요한 것은 제품 기능이 아니라 작은 평가셋을 만들기 위한 입력 도구다.
정적 HTML은 build, server, auth, schema migration 없이 바로 열 수 있고, 최종 산출물을 JSON으로 남길 수 있어 현재 단계에 더 맞다.

## 트레이드오프

- 얻은 것
  - 사용자는 Markdown 표 대신 브라우저 UI에서 query별 관련도와 근거 메모를 입력할 수 있다.
  - 라벨 결과를 JSON으로 export해 나중 benchmark runner 입력으로 사용할 수 있다.
  - 서버/DB 없이 동작하므로 MVP 범위를 키우지 않는다.
- 미룬 것
  - 실제 collected/API-ready article 20-30개를 frozen catalog로 export하는 작업은 아직 남아 있다.
  - Recall@5, MRR@5, Top1 hit, latency를 계산하는 benchmark runner는 아직 없다.
  - 브라우저 플러그인의 local file 접근 정책 때문에 Codex가 screenshot/click/download 자동 검증까지 수행하지는 못했다.
  - 이후 사용자가 실제 브라우저에서 `labeling.html`을 열어 정상 동작을 확인했다.
